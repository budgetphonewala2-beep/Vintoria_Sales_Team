## Who buys this (segments)
- **Seed to Series A SaaS teams** - buying product design capacity to turn working screens into a usable product. Trigger: first paying customers file repeated support tickets about the same screen.
- **Established product organisations with design debt** - buying a UX audit and a design system to stop squads shipping inconsistent UI. Trigger: a second squad starts building screens without shared components.
- **Build agencies and dev shops** - buying white-label design capacity. Trigger: a build contract is signed with no designer attached.
- **Founders relaunching a dated marketing site** - buying website UI design and responsive interface design. Trigger: a rebrand, funding announcement or new positioning goes public.
- **Marketplaces, booking and checkout teams** - buying conversion-focused UX. Trigger: traffic is growing while completed signups or orders stay flat.
- **Post-launch mobile app teams** - buying mobile UI design and usability testing. Trigger: store reviews cite confusion, or a low rating lands on a recent update.
- **Internal tools and analytics owners** - buying dashboard design and information architecture. Trigger: a new data platform or BI rollout exposes unusable reports.
- **Enterprise portals serving external users** - buying UX research, IA and accessibility-aware interface work. Trigger: a support backlog forms around a portal users cannot navigate.

## Buying signals (observable)
- Careers page advertises a product design or UX role whose requirements name design systems (090, 100).
- Header, button or form control styles differ between pages in a screenshot set taken in one session (081, 091).
- Primary flow breaks on a 390px viewport, with horizontal scroll or clipped text visible (101).
- Product screenshots show no empty, error or loading states (082, 093).
- Pricing page shows a single plan with one long undifferentiated feature table (096).
- Recent app store reviews mention confusing navigation, unclear buttons or hidden actions (087, 099).
- Changelog entries labelled redesign, new navigation or new dashboard (094, 095).
- Frontend job ad says implement designs from Figma and the company lists no designer (102).
- Checkout or contact form asks for more than eight fields with no progress indicator (096, 093).
- Every page uses stock photography or generic illustration in place of product screens (088).
- Portal screenshots show dense tables with no filter, sort or empty state (089, 094).
- Marketing site and live product look like two different companies when compared side by side (085, 088).
- Help centre answers the same navigation question in several separate articles (083, 094).
- No public accessibility statement while the site sells to public sector or enterprise buyers (099, 101).

## Discovery questions
- Which screen do users complain about most, and what do they say?
- Who owns design decisions today, and who signs them off?
- Which flows are measured end to end right now?
- Do you have a component library or a single design file, or is design done screen by screen?
- What fails first when a feature ships: consistency, speed or handoff?
- How many developers or squads build UI from your designs?
- Does the redesign replace the product or run alongside it?
- What did the last design engagement leave unfinished?

## Proof-of-work audit angles
- Count distinct button, input and heading styles across the three highest-traffic templates; report the count and attach captures.
- Load the primary flow at 390px width and record every layout break; report each broken element.
- Walk the signup to first-value path and count steps and required fields; report both counts.
- List every page with no visible primary call to action above the fold; report the page URLs.
- Extract rendered font families and weights on five pages; report the per-page set.
- Tab through the main navigation and primary form; report focus order and missing focus states.
- Compare app store screenshots with the current live build; report visible discrepancies.
- Identify repeated UI patterns implemented differently on different pages; report one paired capture each.
- Measure text contrast for body copy and button labels against rendered colours; report each measured pair.
- Count empty, error and loading states documented in the help centre versus states visible in the product; report both counts.

## Deliverables (what the client receives)
- UX audit report with annotated screen captures
- User journey map per agreed primary flow
- Information architecture map or sitemap
- Wireframe set for agreed screens
- Interactive prototype for agreed flows
- Interface design files for agreed screens
- Design system with component and token documentation
- Design-to-development handoff pack with specs, states and edge cases

## Do not sell when
- No access to users, analytics or support tickets, and no willingness to gather any.
- The decision is held by a committee of more than three people with no named owner.
- They want pixel changes only and refuse a scoped audit.
- A full platform rebuild by another vendor is already scheduled in the same period.
- They ask for a complete redesign before any problem has been named.
- The person asking cannot describe a single user complaint or failed flow.
- Design files would have no consumer because no one builds from them.
