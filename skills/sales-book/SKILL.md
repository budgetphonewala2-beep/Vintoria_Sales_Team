# Meeting Booking

Getting to "yes, let's talk" is hard; losing it to back-and-forth about times is avoidable. You make booking take one email.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Read `SELLER-PROFILE.json` if it exists (`python <SCRIPTS>/seller_profile.py show`). If it doesn't,
   carry on with what the user told you and suggest `sales-setup` at the end — don't block urgent work on it.
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Every fact you write must trace to a script output, a page saved with `fetch_page.py --save`, the
   prospect's own words or the seller's profile — never to memory or to a document you wrote yourself. Never invent
   people, titles, emails, connections, results, prices or metrics: one invented detail in a cold email destroys trust
   and can break consumer-protection law. Unknown = "Not found"; a guessed email = `pattern-guessed — verify before
   sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`. Never say something was sent, booked, verified or
   scanned unless a script's output says so. The guards: `../sales/references/truth-rules.md`.

## Steps

1. **Who and where.** Read `python <SCRIPTS>/pipeline.py show <slug>`. Work out the prospect's time zone from their post, site
   address, phone code (+91 India, +1 US/Canada, +44 UK, +61 Australia) or email signature; if unsure, ask.
2. **If they named a time**, use it (check it with `python <SCRIPTS>/meeting.py slots` only if it may clash). Otherwise propose:
   `python <SCRIPTS>/meeting.py slots --prospect-tz <IANA zone> [--count 3] [--minutes 30]`
   It returns 2 slots on different days in both zones (two concrete times get a faster yes than a bare link), avoiding meetings already booked, plus a ready
   message that includes `BOOKING_URL` if the user has one (Cal.com, Calendly, Google booking page). Slots
   marked `outside_your_work_hours` need the user's OK (common for Asia ↔ US). Record where they are once:
   `python <SCRIPTS>/pipeline.py where <slug> --country US --tz America/Chicago` — follow-ups then land in their morning too.
3. Write the booking email: one line of context + the slots + the link. Claim-check it, the user sends it,
   then `python <SCRIPTS>/outreach.py log <slug> --channel email --to <email> --subject "..." --no-schedule`.
4. **When they confirm**, book it:
   `python <SCRIPTS>/meeting.py book <slug> --start "YYYY-MM-DD HH:MM" [--tz <zone the time is in>] --prospect-tz <their zone> --attendee <email> --attendee-name "<name>" [--link <video link>] [--agenda "<one line>"]`
   This writes `prospects/<slug>/MEETING-<date>.ics`, sets the stage to `meeting`, stops follow-ups and
   schedules prep for the day before. Give the user the confirmation message and tell them to attach the `.ics`.
5. **Before the meeting:** run `sales-prep`; the day before, give the user a confirmation that carries something
   useful — the agenda plus the 2-3 audit findings you'll walk through (a pre-read raises show rates); an hour
   before, a one-line reminder.
6. **After the meeting:** `python <SCRIPTS>/meeting.py outcome <id> held|no_show|rescheduled|cancelled --notes "<what was agreed>"`.
   Held → `python <SCRIPTS>/pipeline.py stage <slug> proposal` when a proposal is due and run `sales-followup` (post-meeting recap)
   and `sales-proposal`. No-show → the same day, one warm note with 2 new slots (step 2); a second no-show moves
   them to `nurture` automatically. Rescheduled → book the new time.

## Settings (in `~/.ai-sales-team/.env`)
`TIMEZONE` (default Asia/Kolkata), `WORK_HOURS` (10:00-18:00), `EXTENDED_HOURS` (07:00-23:00, used only
when time zones barely overlap), `WORK_DAYS` (Mon-Fri), `MEETING_MINUTES` (30), `BOOKING_URL`, `MEETING_LINK`,
`SENDER_NAME`, `SENDER_EMAIL`. Ask the user once and suggest they add them.

## Rules
- The booking link goes out only after they've shown interest; `outreach.py` refuses it in cold emails.
- When they book through the link, `python <SCRIPTS>/inbox.py check --apply` (and the autopilot) spots the Calendly / Cal.com /
  calendar-invite email, records the meeting with its time, moves the stage and schedules prep — no manual step.
  With `AUTO_REPLY=1` and IMAP, a "let's talk" reply gets the link automatically within one autopilot tick.
- Always show times in **their** zone first, with yours in brackets.
- Never invent a video link: use `--link`, `MEETING_LINK`, or say the link will follow.
- Don't book a time the prospect didn't confirm. A proposed slot is not a meeting.

## Before anything is sent

- **Claim check** every message: `python <SCRIPTS>/claim_check.py --draft <file> --prospect <slug> [--evidence-text "<their post>"]`.
  Rewrite or delete each unsupported sentence and fill every `[PLACEHOLDER]`. Drafts never count as evidence;
  claims about the seller are checked against the real proof in the profile; a hedged consequence ("so phone
  visitors may…") is fine, an unproven number is not.
- **Compliance:** follow `references/compliance.md` — opt-out line, postal address (US), consent rules (UK/EU/CA/AU/NZ).
- **Approval:** show the user the exact final text. Nothing goes out without their OK (a sequence is approved once,
  as a whole).
- **Delivery:** `python <SCRIPTS>/outreach.py doctor` tells you the mode — `autopilot` (queue the approved sequence with
  `outreach.py approve`; it sends each email on its day and stops on any reply), `send-one-by-one` (`outreach.py send`,
  dry run first, then `--send`), or `manual` (the user sends; you `outreach.py log` it so follow-ups get scheduled).
  Never say something was sent unless a script returned `"sent": true` or the user told you so.
- **No booking link** (Calendly, Cal.com, `BOOKING_URL`) until they've replied with interest — a calendar link in a
  cold email reads as presumptuous and lowers replies; `outreach.py` refuses it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
