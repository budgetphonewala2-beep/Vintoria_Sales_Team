# Decision Makers & Verified Contacts

You find the right people and the safest way to reach them. A wrong or guessed address costs
deliverability, so verification status is always shown.

## Before you start

1. **Scripts.** `<SCRIPTS>` means the `scripts/` folder of the `sales` skill — `../sales/scripts/` next to this
   skill's folder. Run them with `python` (Windows) or `python3` (macOS/Linux). Every script prints one JSON
   object. Script output is evidence to check, not truth.
2. **Web access.** Use your agent's own web fetch / search if it has them. Otherwise run
   `python <SCRIPTS>/fetch_page.py <url> [<url> ...]` and `python <SCRIPTS>/web_search.py "<query>"`
   (search needs `BRIGHTDATA_API_KEY`); with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py` searches LinkedIn
   posts, Google and Reddit. If you can't fetch something, write "Not found" — never fill gaps.
3. **Prospect folder.** Files about one prospect live in `prospects/<slug>/` (slug = domain without `www.`,
   e.g. `acme.com`). Given only a name, look for an existing `prospects/*/` folder first, then find the
   official domain. Never use another prospect's files as context. Shared files (`IDEAL-CUSTOMER-PROFILE.md`,
   `OBJECTION-PLAYBOOK.md`, `SALES-REPORT*`) stay in the working-directory root.
4. **Pipeline.** The pipeline database (`~/.ai-sales-team/pipeline.db`) is the source of truth across
   sessions and agents. Record what you learn with `python <SCRIPTS>/pipeline.py ...` (commands below).
5. **What the user sells.** Read `IDEAL-CUSTOMER-PROFILE.md` if it exists. If it doesn't and you don't know
   the offer, ask once: "What do you sell, and to whom?" If the user sells services (agency, freelancer,
   consultant), judge fit by visible need — site quality, public posts asking for help, hiring for the role,
   ad activity — not by funding or headcount.
6. **Facts, not fiction.** Never invent people, titles, emails, mutual connections, customer results,
   funding or metrics. Unknown = "Not found". Pattern-built emails = `pattern-guessed — verify before
   sending`. A missing proof point = a visible `[ADD REAL CUSTOMER RESULT]` marker.

## Steps

1. **People**: if a `DOSSIER.json` exists, start from its `people` and `decision_maker`. Otherwise run
   `python <SCRIPTS>/contact_finder.py --url <url>`, read the team/about pages, and search for leaders
   (`site:linkedin.com/in "<company>" founder OR owner OR director`). A hunt lead already names the person:
   the post author (LinkedIn profile URL, HN/Reddit username). Only list people you found evidence for.
2. **Roles**: classify each as Economic Buyer, Champion, Technical Evaluator, User, Influencer or Blocker
   (`references/playbook.md` Phase 2). For an owner-run SMB the owner is usually buyer and champion.
3. **Emails**: for the top 1-3 people run
   `python <SCRIPTS>/find_email.py --domain <domain> --first <first> --last <last>`.
   It runs a waterfall and stops at the first verified address: their post → website → finders
   (Prospeo, Findymail, Hunter, Apollo — whichever keys are set, order in `EMAIL_FINDERS`) → verifiers
   (MillionVerifier, ZeroBounce, NeverBounce, Hunter) on the candidates, or on likely name patterns if nothing
   was found. `find_email.py --providers` shows what is configured.
   If the post or website already shows an address it is used and only verified — no finder credits.
   Use the status exactly as returned: `verified`, `catch_all`, `unverified`, `pattern-guessed`, `invalid`.
   Only `verified` addresses are safe for cold email; say so.
   **Best channel** per person: verified email → email; business phone from the site or Google Maps → WhatsApp
   click-to-chat (`python <SCRIPTS>/outreach.py whatsapp`); only a LinkedIn/Reddit/HN profile → the user replies
   where they posted or sends a DM themselves.
4. **Personalization anchors** and **multi-threading plan** (Phases 3-5).
5. Write `prospects/<slug>/DECISION-MAKERS.md` (`references/output-format.md`).
6. Record each person: `python <SCRIPTS>/pipeline.py contact <slug> --name "<name>" --title "<title>" --role "<buying role>"
   --email <email> --email-status <status> --source <source> --linkedin <url>`.
