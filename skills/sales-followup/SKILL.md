# Follow-Up Sequences

Follow-ups win most deals. You write ones that add value instead of "just checking in".

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Run `python <SCRIPTS>/seller_profile.py check`. This skill builds its queries, emails or prices
   from `SELLER-PROFILE.json`, so if it isn't `Ready.` run the `sales-setup` interview first (when the user is in a
   hurry, ask just the missing required questions in one message and save the answers with `seller_profile.py set`).
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Every fact you write must trace to a script output, a page saved with `fetch_page.py --save`, the
   prospect's own words or the seller's profile — never to memory or to a document you wrote yourself. Never invent
   people, titles, emails, connections, results, prices or metrics: one invented detail in a cold email destroys trust
   and can break consumer-protection law. Unknown = "Not found"; a guessed email = `pattern-guessed — verify before
   sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`. Never say something was sent, booked, verified or
   scanned unless a script's output says so. The guards: `../sales/references/truth-rules.md`.

## Steps

1. Ask (or read) what happened: last touch, what they said, what was promised, pricing shared, objections.
   Read `python <SCRIPTS>/pipeline.py show <slug>` and the prospect folder.
2. Pick the scenario (`references/playbook.md` Step 2): post-meeting, post-demo, post-proposal, ghost recovery
   or nurture, and its cadence. Post-meeting recap goes out within 24 hours: what they said (their words),
   what you agreed, the next step with a date. Post-proposal: day 2 walkthrough offer, day 5 one question on
   the option they liked, day 10 a deadline that is real (start slot, price validity), day 20 breakup.
3. Write the emails plus LinkedIn/phone/SMS touches only where appropriate (SMS only for warm leads who
   shared their number). Reference real details from the conversation.
4. Claim-check every email.
5. Write `prospects/<slug>/FOLLOWUP-SEQUENCE.md` (`references/output-format.md`).
6. Cold sequences already queued with `python <SCRIPTS>/outreach.py approve` need nothing here — they send on day 3, 7, 14, 28.
   Record: `python <SCRIPTS>/pipeline.py note <slug> "<what happened>"`, and log each manual follow-up when it goes out —
   `python <SCRIPTS>/outreach.py log <slug> --channel email --to <email> --subject "..."` (this schedules the next one from the
   cadence) — or `python <SCRIPTS>/pipeline.py next <slug> "<next touch>" --due <date>` for a custom date. Update the stage
   (`replied`, `meeting`, `proposal`, `nurture`, `lost`) when the user tells you. If they replied, use `sales-reply`.

## Before anything is sent

- **Claim check** every message: `python <SCRIPTS>/claim_check.py --draft <file> --prospect <slug> [--evidence-text "<their post>"]`.
  Rewrite or delete each unsupported sentence and fill every `[PLACEHOLDER]`. Drafts never count as evidence;
  claims about the seller are checked against the real proof in the profile; a hedged consequence ("so phone
  visitors may…") is fine, an unproven number is not.
- **Compliance:** follow `references/compliance.md` — opt-out line, postal address (US), consent rules (UK/EU/CA/AU/NZ).
- **Approval:** show the user the exact final text. Nothing goes out without their OK (a sequence is approved once,
  as a whole).
- **Delivery:** `python <SCRIPTS>/outreach.py doctor` tells you the mode — `autopilot` (queue the approved sequence with
  `outreach.py approve`; it sends each email on its day and stops on any reply), `send-one-by-one` (`outreach.py send`,
  dry run first, then `--send`), or `manual` (the user sends; you `outreach.py log` it so follow-ups get scheduled).
  Never say something was sent unless a script returned `"sent": true` or the user told you so.
- **No booking link** (Calendly, Cal.com, `BOOKING_URL`) until they've replied with interest — a calendar link in a
  cold email reads as presumptuous and lowers replies; `outreach.py` refuses it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
