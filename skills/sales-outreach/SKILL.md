# Cold Outreach Sequence

You write outreach a busy owner actually answers: short, specific, true, and easy to say yes to.

## Before you start

1. **Scripts.** `<SCRIPTS>` means the `scripts/` folder of the `sales` skill — `../sales/scripts/` next to this
   skill's folder. Run them with `python` (Windows) or `python3` (macOS/Linux). Every script prints one JSON
   object. Script output is evidence to check, not truth.
2. **Web access.** Use your agent's own web fetch / search if it has them. Otherwise run
   `python <SCRIPTS>/fetch_page.py <url> [<url> ...]` and `python <SCRIPTS>/web_search.py "<query>"`
   (search needs `BRIGHTDATA_API_KEY`); with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py` searches LinkedIn
   posts, Google and Reddit. If you can't fetch something, write "Not found" — never fill gaps.
3. **Prospect folder.** Files about one prospect live in `prospects/<slug>/` (slug = domain without `www.`,
   e.g. `acme.com`). Given only a name, look for an existing `prospects/*/` folder first, then find the
   official domain. Never use another prospect's files as context. Shared files (`IDEAL-CUSTOMER-PROFILE.md`,
   `OBJECTION-PLAYBOOK.md`, `SALES-REPORT*`) stay in the working-directory root.
4. **Pipeline.** The pipeline database (`~/.ai-sales-team/pipeline.db`) is the source of truth across
   sessions and agents. Record what you learn with `python <SCRIPTS>/pipeline.py ...` (commands below).
5. **What the user sells.** Read `IDEAL-CUSTOMER-PROFILE.md` if it exists. If it doesn't and you don't know
   the offer, ask once: "What do you sell, and to whom?" If the user sells services (agency, freelancer,
   consultant), judge fit by visible need — site quality, public posts asking for help, hiring for the role,
   ad activity — not by funding or headcount.
6. **Facts, not fiction.** Never invent people, titles, emails, mutual connections, customer results,
   funding or metrics. Unknown = "Not found". Pattern-built emails = `pattern-guessed — verify before
   sending`. A missing proof point = a visible `[ADD REAL CUSTOMER RESULT]` marker.

## Steps

1. **Evidence first.** If `prospects/<slug>/DOSSIER.json` is missing, run the deep scan:
   `python <SCRIPTS>/prospect_scan.py <url> [--post-text "<their post>" --post-url <url>]`. Read `DOSSIER.md` (ranked hooks, decision maker,
   best email), other `prospects/<slug>/` files and `python <SCRIPTS>/pipeline.py show <slug>`. Recipient must have a `verified` email,
   or say clearly that it isn't.
   **Channel by source:** they posted asking (LinkedIn/Reddit/HN/X/FB) → reply there first (user posts it, 2 lines,
   helpful, no pitch) + email if verified; Google Maps lead with a phone and no email → WhatsApp click-to-chat;
   Product Hunt launch → email the maker or comment on the launch (user).
2. **First email** — follow `references/first-email-guide.md`: plain text, under 120 words, mentions their post
   or business naturally, ONE specific observation backed by evidence, one soft question as the CTA ("worth a
   quick call?"), the user's signature with postal address and an opt-out line. **No booking link** — the goal of
   the cold emails is a reply; the calendar link is sent only once they say yes (`sales-reply` / `sales-book`).
3. **Sequence** — 4 follow-ups on **day 3, 7, 14 and 28** after email 1 (`python <SCRIPTS>/outreach.py cadence`), each adding something
   new, using `references/playbook.md` and the templates `references/template-outreach-cold.md`, `-warm.md`, `-referral.md`:
   | Email | Day | Content | Words |
   |---|---|---|---|
   | 1 | 0 | Their post / top hook + one fact + soft question | ≤ 120 |
   | 2 | 3 | Second hook (another audit fact) + a 1-line fix idea | ≤ 70 |
   | 3 | 7 | Proof: a relevant real result, or a mini teardown of their page (`[ADD REAL CUSTOMER RESULT]` if none) | ≤ 90 |
   | 4 | 14 | Different angle: competitor/market fact (Maps comparison, reviews) or a simple question | ≤ 60 |
   | 5 | 28 | Polite breakup: "close the file?" + leave the door open | ≤ 50 |
   Subject lines: 2-5 words, lower-case, specific ("acme homepage on mobile"), no clickbait; follow-ups reply
   in the same thread. Write in the prospect's language (Hinglish post → simple Hinglish email).
   Use the warm or referral template only for a real, confirmed connection.
4. **Claim check** every email (see "Before anything is sent"); fix until it passes.
5. Write `prospects/<slug>/OUTREACH-SEQUENCE.md` (`references/output-format.md`).
6. Record: `python <SCRIPTS>/pipeline.py attach <slug> prospects/<slug>/OUTREACH-SEQUENCE.md --kind outreach`.
7. **Put it on autopilot** (with SMTP + IMAP set up): save the 5 emails as `prospects/<slug>/SEQUENCE.json`
   (`[{"step": 1, "subject": "...", "body": "..."}, {"step": 2, "body": "..."}, ...]` — follow-ups reply in the same
   thread), show them to the user, and on approval run
   `python <SCRIPTS>/outreach.py approve <slug> --to <email> --file prospects/<slug>/SEQUENCE.json --evidence "prospects/<slug>/*.md" --evidence prospects/<slug>/SITE-AUDIT.json`.
   It checks every email now and queues them; `python <SCRIPTS>/autopilot.py tick --send` (scheduled) sends each on its day and stops
   the moment they reply, opt out, bounce or book.
8. **Or send one at a time** (see "Before anything is sent"): either the user sends it and you log it —
   `python <SCRIPTS>/outreach.py log <slug> --channel email --step 1 --to <email> --subject "<subject>"` — or, if SMTP is set up and the
   user approves this exact email, `python <SCRIPTS>/outreach.py send ...` (dry run first, then `--send`). Logging moves the stage to
   `contacted` and schedules follow-up #1 automatically (`python <SCRIPTS>/outreach.py cadence` shows the schedule).
9. Other channels: LinkedIn/WhatsApp messages are sent by the user; for WhatsApp give a click-to-chat link
   (`python <SCRIPTS>/outreach.py whatsapp <number with country code> --text-file msg.txt`), then log it with `--channel whatsapp`.

## Before anything is sent

- Run the claim check on every email/proposal you write and fix it until it passes:
  `python <SCRIPTS>/claim_check.py --draft <file> --evidence "prospects/<slug>/*.md" [--evidence prospects/<slug>/SITE-AUDIT.json] [--evidence-text "<their post>"]`
  Rewrite or delete each unsupported sentence; fill or remove every `[PLACEHOLDER]`.
- Follow `references/compliance.md` (opt-out line, postal address for US, consent rules for UK/EU/Canada/India).
- Show the user the exact final text and get their approval for **each** message before it goes out.
- Sending: by default the user sends it and you log it with
  `python <SCRIPTS>/outreach.py log <slug> --channel email --to <email> --subject "..."`. Only if SMTP is set up
  and the user approved this email, run `python <SCRIPTS>/outreach.py send <slug> --to ... --subject ... --body-file ... --evidence ...`
  (dry run, all gates must pass) and then the same command with `--send`. Never claim an email was sent unless
  `outreach.py` returned `"sent": true` or the user told you they sent it.
- Whole sequences: after the user approves all emails, queue them with `python <SCRIPTS>/outreach.py approve ...`;
  the scheduled `autopilot.py tick --send` sends each on day 3, 7, 14, 28 and stops on any reply.
- No booking link (Calendly, Cal.com, `BOOKING_URL`) until the prospect has replied with interest.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
