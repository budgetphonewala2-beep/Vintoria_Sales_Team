# Meeting Preparation Brief

You make the user the best-prepared person in the meeting, using what is already known first.

## Before you start

1. **Scripts.** `<SCRIPTS>` means the `scripts/` folder of the `sales` skill — `../sales/scripts/` next to this
   skill's folder. Run them with `python` (Windows) or `python3` (macOS/Linux). Every script prints one JSON
   object. Script output is evidence to check, not truth.
2. **Web access.** Use your agent's own web fetch / search if it has them. Otherwise run
   `python <SCRIPTS>/fetch_page.py <url> [<url> ...]` and `python <SCRIPTS>/web_search.py "<query>"`
   (search needs `BRIGHTDATA_API_KEY`); with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py` searches LinkedIn
   posts, Google and Reddit. If you can't fetch something, write "Not found" — never fill gaps.
3. **Prospect folder.** Files about one prospect live in `prospects/<slug>/` (slug = domain without `www.`,
   e.g. `acme.com`). Given only a name, look for an existing `prospects/*/` folder first, then find the
   official domain. Never use another prospect's files as context. Shared files (`IDEAL-CUSTOMER-PROFILE.md`,
   `OBJECTION-PLAYBOOK.md`, `SALES-REPORT*`) stay in the working-directory root.
4. **Pipeline.** The pipeline database (`~/.ai-sales-team/pipeline.db`) is the source of truth across
   sessions and agents. Record what you learn with `python <SCRIPTS>/pipeline.py ...` (commands below).
5. **What the user sells.** Read `IDEAL-CUSTOMER-PROFILE.md` if it exists. If it doesn't and you don't know
   the offer, ask once: "What do you sell, and to whom?" If the user sells services (agency, freelancer,
   consultant), judge fit by visible need — site quality, public posts asking for help, hiring for the role,
   ad activity — not by funding or headcount.
6. **Facts, not fiction.** Never invent people, titles, emails, mutual connections, customer results,
   funding or metrics. Unknown = "Not found". Pattern-built emails = `pattern-guessed — verify before
   sending`. A missing proof point = a visible `[ADD REAL CUSTOMER RESULT]` marker.

## Steps

1. Load everything known: `python <SCRIPTS>/pipeline.py show <slug>`, `python <SCRIPTS>/meeting.py list`, all files in `prospects/<slug>/` (`DOSSIER.md`,
   post quote, SITE-AUDIT, research, contacts, outreach, replies). If there's no dossier, run `python <SCRIPTS>/prospect_scan.py <url>` first.
   Ask for the meeting goal if unknown.
2. Fill gaps with fresh research on the company and each attendee (`references/playbook.md` Step 1).
3. Build the brief (Step 2): cheat sheet first; then snapshot, attendees, their original request in their own
   words, audit facts, the conversation so far, qualification status (budget, timeline, decision maker, scope —
   mark unknowns), talking points, 10 discovery questions aimed at the unknowns, objections, landmines,
   success metrics, next steps to propose, and an agenda (Step 3) for 15/30/60 minutes.
4. Add a **3-minute screen-share plan**: open their site on a phone view, show the top 2 audit facts, show one
   competitor doing it better — then ask, don't pitch. End the brief with the exact ask for the meeting's close
   ("Shall I send a proposal with 2 options by Friday?").
5. Write `prospects/<slug>/MEETING-PREP.md` (`references/output-format.md`, `references/template-meeting-prep.md`).
6. Record: `python <SCRIPTS>/pipeline.py attach <slug> prospects/<slug>/MEETING-PREP.md --kind meeting-prep`. If the meeting isn't in
   the pipeline yet, book it with `sales-book` (`python <SCRIPTS>/meeting.py book ...`) so reminders and outcomes are tracked.
7. Give the user the reminder message to send the day before (from `python <SCRIPTS>/meeting.py list`) and, after the call,
   record the outcome: `python <SCRIPTS>/meeting.py outcome <id> held --notes "<budget, scope, decision date>"`.
