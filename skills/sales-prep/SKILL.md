# Meeting Preparation Brief

You make the user the best-prepared person in the meeting, using what is already known first.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Read `SELLER-PROFILE.json` if it exists (`python <SCRIPTS>/seller_profile.py show`). If it doesn't,
   carry on with what the user told you and suggest `sales-setup` at the end — don't block urgent work on it.
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Every fact you write must trace to a script output, a page saved with `fetch_page.py --save`, the
   prospect's own words or the seller's profile — never to memory or to a document you wrote yourself. Never invent
   people, titles, emails, connections, results, prices or metrics: one invented detail in a cold email destroys trust
   and can break consumer-protection law. Unknown = "Not found"; a guessed email = `pattern-guessed — verify before
   sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`. Never say something was sent, booked, verified or
   scanned unless a script's output says so. The guards: `../sales/references/truth-rules.md`.

## Steps

1. Load everything known: `python <SCRIPTS>/pipeline.py show <slug>`, `python <SCRIPTS>/meeting.py list`, all files in `prospects/<slug>/` (`DOSSIER.md`,
   post quote, SITE-AUDIT, research, contacts, outreach, replies). If there's no dossier, run `python <SCRIPTS>/prospect_scan.py <url>` first.
   Ask for the meeting goal if unknown.
2. Fill gaps with fresh research on the company and each attendee (`references/playbook.md` Step 1).
3. Build the brief (Step 2): cheat sheet first; then snapshot, attendees, their original request in their own
   words, audit facts, the conversation so far, qualification status (budget, timeline, decision maker, scope —
   mark unknowns), talking points, 10 discovery questions aimed at the unknowns, objections, landmines,
   success metrics, next steps to propose, and an agenda (Step 3) for 15/30/60 minutes.
4. Add a **3-minute screen-share plan**: open their site on a phone view, show the top 2 audit facts, show one
   competitor doing it better — then ask, don't pitch. End the brief with the exact ask for the meeting's close
   ("Shall I send a proposal with 2 options by Friday?").
5. Write `prospects/<slug>/MEETING-PREP.md` (`references/output-format.md`, `references/template-meeting-prep.md`) and run
   `python <SCRIPTS>/claim_check.py --draft prospects/<slug>/MEETING-PREP.md --prospect <slug>` — talking points built on an
   invented fact are worse than none.
6. Record: `python <SCRIPTS>/pipeline.py attach <slug> prospects/<slug>/MEETING-PREP.md --kind meeting-prep`. If the meeting isn't in
   the pipeline yet, book it with `sales-book` (`python <SCRIPTS>/meeting.py book ...`) so reminders and outcomes are tracked.
7. Give the user the reminder message to send the day before (from `python <SCRIPTS>/meeting.py list`) and, after the call,
   record the outcome: `python <SCRIPTS>/meeting.py outcome <id> held --notes "<budget, scope, decision date>"`.
