# Full Prospect Analysis

You run the deepest analysis in the team: discovery, five role playbooks, a weighted score, an action
plan and a ready first email for `prospects/<slug>/PROSPECT-ANALYSIS.md`.

## Before you start

1. **Scripts.** `<SCRIPTS>` means the `scripts/` folder of the `sales` skill — `../sales/scripts/` next to this
   skill's folder. Run them with `python` (Windows) or `python3` (macOS/Linux). Every script prints one JSON
   object. Script output is evidence to check, not truth.
2. **Web access.** Use your agent's own web fetch / search if it has them. Otherwise run
   `python <SCRIPTS>/fetch_page.py <url> [<url> ...]` and `python <SCRIPTS>/web_search.py "<query>"`
   (search needs `BRIGHTDATA_API_KEY`). If you can't fetch something, write "Not found" — never fill gaps.
3. **Prospect folder.** Files about one prospect live in `prospects/<slug>/` (slug = domain without `www.`,
   e.g. `acme.com`). Given only a name, look for an existing `prospects/*/` folder first, then find the
   official domain. Never use another prospect's files as context. Shared files (`IDEAL-CUSTOMER-PROFILE.md`,
   `OBJECTION-PLAYBOOK.md`, `SALES-REPORT*`) stay in the working-directory root.
4. **Pipeline.** The pipeline database (`~/.ai-sales-team/pipeline.db`) is the source of truth across
   sessions and agents. Record what you learn with `python <SCRIPTS>/pipeline.py ...` (commands below).
5. **What the user sells.** Read `IDEAL-CUSTOMER-PROFILE.md` if it exists. If it doesn't and you don't know
   the offer, ask once: "What do you sell, and to whom?" If the user sells services (agency, freelancer,
   consultant), judge fit by visible need — site quality, public posts asking for help, hiring for the role,
   ad activity — not by funding or headcount.
6. **Facts, not fiction.** Never invent people, titles, emails, mutual connections, customer results,
   funding or metrics. Unknown = "Not found". Pattern-built emails = `pattern-guessed — verify before
   sending`. A missing proof point = a visible `[ADD REAL CUSTOMER RESULT]` marker.

## Steps

1. **Discovery** (see `references/playbook.md` Phase 1): fetch the homepage and key pages, detect company type
   and industry, run `python <SCRIPTS>/analyze_prospect.py --url <url>` and
   `python <SCRIPTS>/site_audit.py --url <url> --save prospects/<slug>/SITE-AUDIT.json`, read any existing
   files in `prospects/<slug>/`, and write a short discovery briefing.
2. **Roles** (Phase 2): follow, in this order, `references/role-company.md`, `role-contacts.md`,
   `role-opportunity.md`, `role-competitive.md`, then `role-strategy.md` (which needs the other four). Each
   returns a 0-100 category score with evidence. If your agent can run subagents, the first four may run in
   parallel; the default is sequential and works everywhere.
3. **Score** (Phase 3): Prospect Score = Company Fit 25% + Contact Access 20% + Opportunity 20% +
   Competitive 15% + Outreach Readiness 20%. Missing role = 50 and lower confidence.
4. **Write** `prospects/<slug>/PROSPECT-ANALYSIS.md` in the format of `references/output-format.md`:
   summary, score breakdown, company profile, decision makers, BANT/MEDDIC, competition, strategy, action plan,
   first email.
5. **Record**:
   `python <SCRIPTS>/pipeline.py add --url <url> --name "<company>" --stage researched`
   `python <SCRIPTS>/pipeline.py score <slug> <score> --breakdown '{"company_fit": .., "contact_access": .., "opportunity": .., "competitive": .., "outreach_readiness": ..}'`
   `python <SCRIPTS>/pipeline.py attach <slug> prospects/<slug>/PROSPECT-ANALYSIS.md --kind prospect-analysis`
   `python <SCRIPTS>/pipeline.py next <slug> "<first action>" --due <YYYY-MM-DD>` and one `contact` line per named decision maker.
6. **Terminal summary**: score + grade, top 3 reasons, the first email, the next skill to run.

## Before anything is sent

- Run the claim check on every email/proposal you write and fix it until it passes:
  `python <SCRIPTS>/claim_check.py --draft <file> --evidence "prospects/<slug>/*.md" [--evidence prospects/<slug>/SITE-AUDIT.json] [--evidence-text "<their post>"]`
  Rewrite or delete each unsupported sentence; fill or remove every `[PLACEHOLDER]`.
- Follow `references/compliance.md` (opt-out line, postal address for US, consent rules for UK/EU/Canada/India).
- Show the user the exact final text and get their approval for **each** message before it goes out.
- Sending: by default the user sends it and you log it with
  `python <SCRIPTS>/outreach.py log <slug> --channel email --to <email> --subject "..."`. Only if SMTP is set up
  and the user approved this email, run `python <SCRIPTS>/outreach.py send <slug> --to ... --subject ... --body-file ... --evidence ...`
  (dry run, all gates must pass) and then the same command with `--send`. Never claim an email was sent unless
  `outreach.py` returned `"sent": true` or the user told you they sent it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
