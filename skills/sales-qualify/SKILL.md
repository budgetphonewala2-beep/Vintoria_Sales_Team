# Lead Qualification (BANT + MEDDIC)

You decide whether a prospect deserves time, and what is still unknown.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Run `python <SCRIPTS>/seller_profile.py check`. This skill builds its queries, emails or prices
   from `SELLER-PROFILE.json`, so if it isn't `Ready.` run the `sales-setup` interview first (when the user is in a
   hurry, ask just the missing required questions in one message and save the answers with `seller_profile.py set`).
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Every fact you write must trace to a script output, a page saved with `fetch_page.py --save`, the
   prospect's own words or the seller's profile — never to memory or to a document you wrote yourself. Never invent
   people, titles, emails, connections, results, prices or metrics: one invented detail in a cold email destroys trust
   and can break consumer-protection law. Unknown = "Not found"; a guessed email = `pattern-guessed — verify before
   sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`. Never say something was sent, booked, verified or
   scanned unless a script's output says so. The guards: `../sales/references/truth-rules.md`.

## Steps

1. Gather evidence: existing `prospects/<slug>/` files, the user's notes and the prospect's replies, plus
   fresh research where needed (`references/playbook.md`).
2. Assess BANT (Budget, Authority, Need, Timeline — 25 each) and MEDDIC (Metrics, Economic buyer, Decision
   criteria, Decision process, Identify pain, Champion), each with evidence or "Unknown".
3. Cross-check with the script:
   - B2B account: write signals to `prospects/<slug>/_bant_signals.json` (`python <SCRIPTS>/lead_scorer.py --example`
     shows the format) and run `python <SCRIPTS>/lead_scorer.py prospects/<slug>/_bant_signals.json`.
   - Someone who asked for a service publicly: `python <SCRIPTS>/lead_scorer.py --mode agency <file>`.
   If your score and the script differ by more than 15, explain why.
4. **Service-buyer checks** (agencies/freelancers): budget stated or implied (₹/$ range, "cheap" = flag),
   decision maker = the poster/owner?, timeline trigger (launch, festive season, event, "ASAP"), scope clarity,
   red flags (wants free samples/spec work, "just exploring", equity-only, unrealistic budget for scope, many
   agencies already in the comments). Two or more red flags → `nurture` or `disqualified`, fast.
5. Write `prospects/<slug>/LEAD-QUALIFICATION.md` (`references/output-format.md`), including the 3-5
   discovery questions that would close the biggest gaps (budget range, decision process, timeline, success
   measure, what went wrong last time).
6. Record: `python <SCRIPTS>/pipeline.py score <slug> <score>`, `python <SCRIPTS>/pipeline.py stage <slug> qualified --reason "<grade + main reason>"`
   (or `disqualified` / `nurture`), `python <SCRIPTS>/pipeline.py next <slug> "<next step>"`.
