# Lead Qualification (BANT + MEDDIC)

You decide whether a prospect deserves time, and what is still unknown.

## Before you start

1. **Scripts.** `<SCRIPTS>` means the `scripts/` folder of the `sales` skill — `../sales/scripts/` next to this
   skill's folder. Run them with `python` (Windows) or `python3` (macOS/Linux). Every script prints one JSON
   object. Script output is evidence to check, not truth.
2. **Web access.** Use your agent's own web fetch / search if it has them. Otherwise run
   `python <SCRIPTS>/fetch_page.py <url> [<url> ...]` and `python <SCRIPTS>/web_search.py "<query>"`
   (search needs `BRIGHTDATA_API_KEY`); with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py` searches LinkedIn
   posts, Google and Reddit. If you can't fetch something, write "Not found" — never fill gaps.
3. **Prospect folder.** Files about one prospect live in `prospects/<slug>/` (slug = domain without `www.`,
   e.g. `acme.com`). Given only a name, look for an existing `prospects/*/` folder first, then find the
   official domain. Never use another prospect's files as context. Shared files (`IDEAL-CUSTOMER-PROFILE.md`,
   `OBJECTION-PLAYBOOK.md`, `SALES-REPORT*`) stay in the working-directory root.
4. **Pipeline.** The pipeline database (`~/.ai-sales-team/pipeline.db`) is the source of truth across
   sessions and agents. Record what you learn with `python <SCRIPTS>/pipeline.py ...` (commands below).
5. **Know the seller first.** Run `python <SCRIPTS>/seller_profile.py check`. If the profile is missing or not
   `Ready.`, stop and run the `sales-setup` interview before anything else — every query, filter, email,
   proposal and send time is built from `SELLER-PROFILE.json`. Then read `IDEAL-CUSTOMER-PROFILE.md` if it exists.
   For service sellers (agency, freelancer, consultant) judge fit by visible need — site quality, public posts
   asking for help, hiring for the role, ad activity — not by funding or headcount.
6. **Facts, not fiction.** Never invent people, titles, emails, mutual connections, customer results,
   funding or metrics. Unknown = "Not found". Pattern-built emails = `pattern-guessed — verify before
   sending`. A missing proof point = a visible `[ADD REAL CUSTOMER RESULT]` marker.

## Steps

1. Gather evidence: existing `prospects/<slug>/` files, the user's notes and the prospect's replies, plus
   fresh research where needed (`references/playbook.md`).
2. Assess BANT (Budget, Authority, Need, Timeline — 25 each) and MEDDIC (Metrics, Economic buyer, Decision
   criteria, Decision process, Identify pain, Champion), each with evidence or "Unknown".
3. Cross-check with the script:
   - B2B account: write signals to `prospects/<slug>/_bant_signals.json` (`python <SCRIPTS>/lead_scorer.py --example`
     shows the format) and run `python <SCRIPTS>/lead_scorer.py prospects/<slug>/_bant_signals.json`.
   - Someone who asked for a service publicly: `python <SCRIPTS>/lead_scorer.py --mode agency <file>`.
   If your score and the script differ by more than 15, explain why.
4. **Service-buyer checks** (agencies/freelancers): budget stated or implied (₹/$ range, "cheap" = flag),
   decision maker = the poster/owner?, timeline trigger (launch, festive season, event, "ASAP"), scope clarity,
   red flags (wants free samples/spec work, "just exploring", equity-only, unrealistic budget for scope, many
   agencies already in the comments). Two or more red flags → `nurture` or `disqualified`, fast.
5. Write `prospects/<slug>/LEAD-QUALIFICATION.md` (`references/output-format.md`), including the 3-5
   discovery questions that would close the biggest gaps (budget range, decision process, timeline, success
   measure, what went wrong last time).
6. Record: `python <SCRIPTS>/pipeline.py score <slug> <score>`, `python <SCRIPTS>/pipeline.py stage <slug> qualified --reason "<grade + main reason>"`
   (or `disqualified` / `nurture`), `python <SCRIPTS>/pipeline.py next <slug> "<next step>"`.
