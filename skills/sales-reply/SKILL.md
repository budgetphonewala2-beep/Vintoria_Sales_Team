# Reply Handling

A reply is the most valuable moment in the pipeline. Answer fast, answer exactly what they asked, and move to a call.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Read `SELLER-PROFILE.json` if it exists (`python <SCRIPTS>/seller_profile.py show`). If it doesn't,
   carry on with what the user told you and suggest `sales-setup` at the end — don't block urgent work on it.
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Never invent people, titles, emails, connections, results, prices or metrics — one invented detail
   in a cold email destroys trust and can break consumer-protection law. Unknown = "Not found"; a guessed email =
   `pattern-guessed — verify before sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`.

## Steps

1. Get the reply text and find the prospect: `python <SCRIPTS>/pipeline.py find <sender email or name>` (then `python <SCRIPTS>/pipeline.py show <slug>` for the
   thread so far, their country/time zone and the stage). Unknown sender → ask the user which prospect it is.
2. Classify and update the pipeline in one go. With IMAP set up, `python <SCRIPTS>/inbox.py check --apply` does this for every new
   reply and bounce (read-only); otherwise the user pastes the reply and you run
   `python <SCRIPTS>/reply_triage.py --file reply.txt --apply <slug> [--from <their email>]`. Either way the queued sequence stops.
   Read the reply yourself too — if the script's category is wrong, say so and fix the stage with `python <SCRIPTS>/pipeline.py stage`.
3. Act on the category:
   | Category | What you write |
   |---|---|
   | `meeting_request` | Go straight to `sales-book`: confirm the time they named, or offer 2-3 slots |
   | `interested` / `question` | Answer in 1-3 sentences (facts only from the ICP / their files), then offer 2-3 slots in their time zone (`python <SCRIPTS>/meeting.py slots --prospect-tz <their tz from show, or ask>`) and the booking link — now it is welcome |
   | `objection_price` / `_has_vendor` | Use `OBJECTION-PLAYBOOK.md` or `sales-objections`; offer a smaller first step, then a call |
   | `objection_timing` | Agree a date; `python <SCRIPTS>/pipeline.py next <slug> "Check back as agreed" --due <date>`; stage stays `nurture` |
   | `referral` | Thank them; write a 3-line email to the named person mentioning who referred you (`sales-outreach`) |
   | `out_of_office` | No reply; `python <SCRIPTS>/pipeline.py next <slug> "Follow up after they return" --due <return date + 1>` |
   | `not_interested` | One gracious line, no pitch; never follow up again |
   | `unsubscribe` | Nothing to write. It's already suppressed — confirm to the user |
   | `bounce` | Find another verified contact with `sales-contacts` |
4. **Keep it short:** at most ~100 words before the slots/link and signature — answer their questions in the first
   two sentences, one honest caveat if there is one, then the call. A busy buyer reads a reply on a phone; long
   replies and several `[TO CONFIRM]` blocks slow the user down. Use at most one `[TO CONFIRM]` and list any other
   open points in your message to the user instead.
5. Claim-check the answer (see "Before anything is sent"), show it to the user, and log it when it's sent:
   `python <SCRIPTS>/outreach.py log <slug> --channel email --to <email> --subject "Re: <their subject>" --no-schedule`.
6. Tell the user the new stage and the next step with its due date (`python <SCRIPTS>/pipeline.py show <slug>`).

## Rules
- Reply within the hour for `meeting_request` and `interested` — speed decides most deals.
- Answer what they asked first. Don't paste the whole pitch again.
- Never claim a price, timeline or result the user hasn't confirmed; use `[TO CONFIRM: ...]` and ask.
- Reply in plain English that matches their tone and spelling (US vs UK); short beats formal.

## Before anything is sent

- **Claim check** every message: `python <SCRIPTS>/claim_check.py --draft <file> --prospect <slug> [--evidence-text "<their post>"]`.
  Rewrite or delete each unsupported sentence and fill every `[PLACEHOLDER]`. Drafts never count as evidence;
  claims about the seller are checked against the real proof in the profile; a hedged consequence ("so phone
  visitors may…") is fine, an unproven number is not.
- **Compliance:** follow `references/compliance.md` — opt-out line, postal address (US), consent rules (UK/EU/CA/AU/NZ).
- **Approval:** show the user the exact final text. Nothing goes out without their OK (a sequence is approved once,
  as a whole).
- **Delivery:** `python <SCRIPTS>/outreach.py doctor` tells you the mode — `autopilot` (queue the approved sequence with
  `outreach.py approve`; it sends each email on its day and stops on any reply), `send-one-by-one` (`outreach.py send`,
  dry run first, then `--send`), or `manual` (the user sends; you `outreach.py log` it so follow-ups get scheduled).
  Never say something was sent unless a script returned `"sent": true` or the user told you so.
- **No booking link** (Calendly, Cal.com, `BOOKING_URL`) until they've replied with interest — a calendar link in a
  cold email reads as presumptuous and lowers replies; `outreach.py` refuses it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
