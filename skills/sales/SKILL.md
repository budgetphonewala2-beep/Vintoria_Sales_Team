# AI Sales Team — Router

You coordinate a team of sales skills. Work out what the user needs, then follow the matching skill.
Every skill works in any agent: they use shell commands (`python <SCRIPTS>/...`), files and your reasoning.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the `scripts/` folder of the `sales` skill (`../sales/scripts/` next to this skill's
   folder). Run them with `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — treat it as
   evidence to check, not as truth.
2. **The seller.** Read `SELLER-PROFILE.json` if it exists (`python <SCRIPTS>/seller_profile.py show`). If it doesn't,
   carry on with what the user told you and suggest `sales-setup` at the end — don't block urgent work on it.
3. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) for a lead without a website. `python <SCRIPTS>/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
4. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, write
   what you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
5. **Web access.** Use your agent's own fetch/search first; otherwise `python <SCRIPTS>/fetch_page.py <url> ...` and
   `python <SCRIPTS>/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/lead_sources.py`. If you can't fetch
   something, write "Not found".
6. **Facts only.** Every fact you write must trace to a script output, a page saved with `fetch_page.py --save`, the
   prospect's own words or the seller's profile — never to memory or to a document you wrote yourself. Never invent
   people, titles, emails, connections, results, prices or metrics: one invented detail in a cold email destroys trust
   and can break consumer-protection law. Unknown = "Not found"; a guessed email = `pattern-guessed — verify before
   sending`; missing proof = a visible `[ADD REAL CUSTOMER RESULT]`. Never say something was sent, booked, verified or
   scanned unless a script's output says so. The guards: `../sales/references/truth-rules.md`.

## The end-to-end flow

```
sales-setup → sales-icp → sales-hunt (lead_sources) → prospect_scan (dossier) → sales-outreach (approve 5 emails)
   → autopilot sends day 0/3/7/14/28 → inbox.py reply → sales-reply → sales-book → sales-prep → sales-proposal
```
Default for any new prospect: run the deep scan first (`python <SCRIPTS>/prospect_scan.py <url> [--post-text "..."]`),
then write from `DOSSIER.md`. Its `facts` are claim-check evidence.

## Working as a team

One agent can run every step; several agents can split the work by role — Manager, Hunter, Researcher, Writer,
Closer — sharing the profile, the pipeline and `prospects/`. Handoffs are pipeline stages and next actions.
Read `references/team.md` for the roles, daily rhythm, targets and rules.

## Quick snapshot (no files)

1. Fetch the homepage (and `/pricing` or `/about` only if the homepage is thin).
2. Assess: what they do, size signals, fit against `IDEAL-CUSTOMER-PROFILE.md`, visible needs, decision-maker
   visibility. Optionally `python <SCRIPTS>/analyze_prospect.py --url <url>`.
3. Output under 30 lines: estimated score + grade, top 3 opportunities, top 3 concerns, the one skill to run next.
4. Say it is a quick estimate from 1-2 pages.

## One grade scale everywhere

| Score | Grade | Meaning |
|---|---|---|
| 90-100 | A+ | Hot — act today |
| 75-89 | A | Strong — worth real effort |
| 60-74 | B | Qualified — standard approach |
| 40-59 | C | Lukewarm — nurture |
| 0-39 | D | Poor fit — deprioritise |

## Helper scripts (`<SCRIPTS>` = this skill's `scripts/` folder)
