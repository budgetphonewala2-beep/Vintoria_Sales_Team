# Vintoria Outreach — first emails, sequences and follow-ups

You write outreach a busy owner actually answers: short, specific, true, about them, and easy to say yes to.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the engine folder `../vintoria-sales/scripts/` (next to this skill's folder), grouped by
   job: `core/` (pipeline, seller profile), `leads/`, `research/`, `outreach/`, `replies/`, `ops/`. Run them with
   `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — evidence to check, not truth.
2. **Vintoria's profile.** Run `python <SCRIPTS>/core/seller_profile.py check`. Queries, emails and prices are built
   from `SELLER-PROFILE.json`; if it isn't `Ready.`, run `vintoria-setup` first (in a hurry: ask only the missing required
   questions in one message and save them with `seller_profile.py set`).
3. **What Vintoria sells.** 270 services in 12 disciplines — `../vintoria-sales/references/service-catalog.md`. Name a
   service exactly as the catalog does (`192 Shopify Development`), never invent one, and never quote a price, discount or
   date that isn't in the profile (`../vintoria-sales/references/pricing-policy.md`): use `[PRICE TO CONFIRM]`.
4. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) without a website. `python <SCRIPTS>/core/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
5. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, record what
   you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
6. **Web access.** Your agent's own fetch/search first; otherwise `python <SCRIPTS>/research/fetch_page.py <url> ...` and
   `python <SCRIPTS>/research/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/leads/lead_sources.py`. If you
   can't fetch something, write "Not found".
7. **Facts only.** Every fact traces to a script output, a page saved with `fetch_page.py --save`, the prospect's own
   words, the catalog or the profile — never to memory or to a document you wrote yourself. One invented client, number or
   promise in a cold email destroys trust and can break consumer-protection law. Unknown = "Not found"; a guessed email =
   `pattern-guessed — verify before sending`; missing proof = `[ADD REAL CUSTOMER RESULT]`. Never say something was sent,
   booked, verified or scanned unless a script's output says so. Guards: `../vintoria-sales/references/truth-rules.md`.

## Cold sequence (new prospect)

1. **Evidence first.** No `prospects/<slug>/DOSSIER.json`? Run the deep scan (`vintoria-prospect-research`). Read
   `DOSSIER.md` (ranked hooks, "Who wrote it", decision maker, best email), `OFFER.md` (which lane and entry service this
   prospect fits) and `python <SCRIPTS>/core/pipeline.py show <slug>`. The recipient needs a `verified` email — or say clearly that it isn't.
   **Channel by source:** they posted asking → the user replies there first (2 helpful lines, no pitch) + email if
   verified; a Maps lead with a phone and no email → WhatsApp click-to-chat; a Product Hunt launch → email the maker.
2. **Email 1** (`references/first-email-guide.md`): plain text, under 120 words, their post or business in the first
   line, ONE observation backed by evidence, one sentence on what Vintoria does about it (one named catalog service —
   never a list), one soft question as the CTA ("worth a quick look?"), signature with postal address and an opt-out line.
   **No booking link** — the goal is a reply; the calendar link follows a yes.
3. **The sequence** (`python <SCRIPTS>/outreach/outreach.py cadence`), each email adding something new (`references/outreach-playbook.md`, templates
   `references/template-outreach-cold.md`, `references/template-outreach-warm.md`, `references/template-outreach-referral.md`):
   | Email | Day | Content | Words |
   |---|---|---|---|
   | 1 | 0 | Their post / top hook + one fact + soft question | ≤ 120 |
   | 2 | 3 | Second hook (another audit fact) + a one-line fix idea | ≤ 70 |
   | 3 | 7 | Proof: a real result from the profile, or a mini teardown of their page (`[ADD REAL CUSTOMER RESULT]` if none) | ≤ 90 |
   | 4 | 14 | Different angle: a competitor or market fact (Maps comparison, reviews) or one simple question | ≤ 60 |
   | 5 | 28 | Polite breakup — "close the file?" — door left open | ≤ 50 |
   Subjects: 2-5 words, lower case, specific ("acme homepage on mobile"); follow-ups reply in the same thread. Signature,
   offer line and proof only from `python <SCRIPTS>/core/seller_profile.py show`. Warm/referral templates only for a real, confirmed connection.
4. **Write the files.** `prospects/<slug>/SEQUENCE.json` is the source of truth
   (`[{"step": 1, "subject": "...", "subject_b": "...", "hook": "<dossier hook key>", "body": "..."}, {"step": 2, "body": "..."}, ...]`;
   `subject_b` runs an A/B test, `hook` feeds `learn.py`). `OUTREACH-SEQUENCE.md` is the human view
   (`references/outreach-output-format.md`) with the same emails, both subjects and the LinkedIn/WhatsApp touches.
5. **Check all five at once:** `python <SCRIPTS>/outreach/outreach.py approve <slug> --to <email> --file prospects/<slug>/SEQUENCE.json --check` runs the
   claim check, the quality score (`python <SCRIPTS>/outreach/email_lint.py --sequence prospects/<slug>/SEQUENCE.json --prospect <slug>`, must reach
   `LINT_MIN_SCORE`, default 80 — aim for **85+ on every email**: the first two lines only this prospect could receive,
   no sentence over 28 words, every follow-up brings a new fact, idea or result), and the opt-out, address, booking-link,
   over-contact and recipient gates — and queues nothing. Before that, run the panel review and the deletion test in
   `references/quality.md`. Fix and re-run until it passes.
6. **Show the user and deliver** in the mode `python <SCRIPTS>/outreach/outreach.py doctor` reports — `autopilot`: after approval run the same command
   without `--check` (each email goes out on its day in their morning; everything stops on a reply, opt-out, bounce or
   booking); `send-one-by-one` / `manual`: see "Before anything is sent".
7. Record: `python <SCRIPTS>/core/pipeline.py attach <slug> prospects/<slug>/OUTREACH-SEQUENCE.md --kind outreach`. WhatsApp:
   `python <SCRIPTS>/outreach/outreach.py whatsapp <number with country code> --text-file msg.txt` gives the user a click-to-chat link; log it with `--channel whatsapp`.

## Follow-ups (after something happened)

1. Read what happened — last touch, their words, what was promised, prices shared, objections — from `python <SCRIPTS>/core/pipeline.py show <slug>`
   and the folder. If they replied, use `vintoria-reply-book` instead.
2. Pick the scenario (`references/followup-playbook.md`): **post-meeting** recap within 24 h (their words, what was agreed,
   next step with a date); **post-proposal** day 2 walkthrough offer, day 5 one question on the option they liked, day 10 a
   real deadline (start slot, price validity), day 20 breakup; **ghost recovery**; **nurture**.
3. Write the emails (plus LinkedIn/phone/SMS only where appropriate — SMS only for warm leads who shared their number),
   claim-check each, write `FOLLOWUP-SEQUENCE.md` (`references/followup-output-format.md`).
4. Queued cold sequences need nothing here. Log a manual follow-up when it goes out:
   `python <SCRIPTS>/outreach/outreach.py log <slug> --channel email --to <email> --subject "..."` (schedules the next one), or
   `python <SCRIPTS>/core/pipeline.py next <slug> "<next touch>" --due <date>`; update the stage when the user tells you.

## Before anything is sent

- **Claim check** every message: `python <SCRIPTS>/outreach/claim_check.py --draft <file> --prospect <slug> [--evidence-text "<their post>"]`.
  Rewrite or delete each unsupported sentence and fill every `[PLACEHOLDER]`. Drafts never count as evidence;
  claims about the seller are checked against the real proof in the profile; a hedged consequence ("so phone
  visitors may…") is fine, an unproven number is not.
- **Compliance:** follow `references/compliance.md` — opt-out line, postal address (US), consent rules (UK/EU/CA/AU/NZ).
- **Approval:** show the user the exact final text. Nothing goes out without their OK (a sequence is approved once,
  as a whole).
- **Quality bar:** score it with `../vintoria-sales/references/quality-bar.md` (emails: 80 to show, 85+ is premium).
- **Language:** plain English by default — US spelling for US/CA, UK spelling for UK/IE/AU/NZ, clear Indian English for
  India (no "do the needful", "revert", "kindly"). If an Indian prospect wrote in Hindi or Hinglish, answer in the same
  register, still short and professional. Prices only in their currency and only from the profile.
- **Delivery:** `python <SCRIPTS>/outreach/outreach.py doctor` tells you the mode — `autopilot` (queue the approved sequence with
  `outreach.py approve`; it sends each email on its day and stops on any reply), `send-one-by-one` (`outreach.py send`,
  dry run first, then `--send`), or `manual` (the user sends; you `outreach.py log` it so follow-ups get scheduled).
  Never say something was sent unless a script returned `"sent": true` or the user told you so.
- **No booking link** (Calendly, Cal.com, `BOOKING_URL`) until they've replied with interest — a calendar link in a
  cold email reads as presumptuous and lowers replies; `outreach.py` refuses it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
