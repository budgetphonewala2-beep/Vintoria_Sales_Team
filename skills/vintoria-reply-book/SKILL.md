# Vintoria Replies & Booking — answer fast, book the call

A reply is the most valuable moment in the pipeline. Answer what they asked, fast, and move to a call in one email.

## Before you start

1. **Scripts.** `<SCRIPTS>` is the engine folder `../vintoria-sales/scripts/` (next to this skill's folder), grouped by
   job: `core/` (pipeline, seller profile), `leads/`, `research/`, `outreach/`, `replies/`, `ops/`. Run them with
   `python` (Windows) or `python3` (macOS/Linux). Each prints one JSON object — evidence to check, not truth.
2. **Vintoria's profile.** Read `SELLER-PROFILE.json` if it exists (`python <SCRIPTS>/core/seller_profile.py show`). If it
   doesn't, carry on with what the user told you and suggest `vintoria-setup` at the end — never block urgent work on it.
3. **What Vintoria sells.** 270 services in 12 disciplines — `../vintoria-sales/references/service-catalog.md`. Name a
   service exactly as the catalog does (`192 Shopify Development`), never invent one, and never quote a price, discount or
   date that isn't in the profile (`../vintoria-sales/references/pricing-policy.md`): use `[PRICE TO CONFIRM]`.
4. **The prospect.** Everything about one prospect lives in `prospects/<slug>/` — slug = their domain (`acme.com`), or
   `name@platform` (`anita-desai@linkedin`) without a website. `python <SCRIPTS>/core/pipeline.py find <email|name|domain>`
   finds it. Never use one prospect's facts for another.
5. **The pipeline.** `~/.ai-sales-team/pipeline.db` is shared by every agent and session. Before you finish, record what
   you learned (stage, note, next action, attached file) — the next agent only sees what the pipeline shows.
6. **Web access.** Your agent's own fetch/search first; otherwise `python <SCRIPTS>/research/fetch_page.py <url> ...` and
   `python <SCRIPTS>/research/web_search.py "<query>"`; with `APIFY_TOKEN`, `python <SCRIPTS>/leads/lead_sources.py`. If you
   can't fetch something, write "Not found".
7. **Facts only.** Every fact traces to a script output, a page saved with `fetch_page.py --save`, the prospect's own
   words, the catalog or the profile — never to memory or to a document you wrote yourself. One invented client, number or
   promise in a cold email destroys trust and can break consumer-protection law. Unknown = "Not found"; a guessed email =
   `pattern-guessed — verify before sending`; missing proof = `[ADD REAL CUSTOMER RESULT]`. Never say something was sent,
   booked, verified or scanned unless a script's output says so. Guards: `../vintoria-sales/references/truth-rules.md`.

## Reply

1. **Find the prospect:** `python <SCRIPTS>/core/pipeline.py find <sender email or name>`, then `python <SCRIPTS>/core/pipeline.py show <slug>` (thread, country, time zone,
   stage). Unknown sender → ask which prospect it is.
2. **Classify and update in one go.** With IMAP: `python <SCRIPTS>/replies/inbox.py check --apply` (every new reply and bounce, read-only).
   Otherwise: `python <SCRIPTS>/replies/reply_triage.py --file reply.txt --apply <slug> [--from <their email>]`. Either way the queued sequence stops.
   Read the reply yourself too — if the category is wrong, say so and fix it with `python <SCRIPTS>/core/pipeline.py stage`.
3. **Answer by category:**
   | Category | What you write |
   |---|---|
   | `meeting_request` | Book it (below): confirm their time or offer 2 slots |
   | `interested` / `question` | Answer in 1-3 sentences (facts only from the profile, `OFFER.md` and their files), then 2 slots in their zone and the booking link — now it is welcome |
   | `objection_price` / `objection_has_vendor` | Use `../vintoria-close/references/objections-playbook.md`: change scope, never the price; offer a smaller first phase, then a call |
   | `objection_timing` | Agree a date; `python <SCRIPTS>/core/pipeline.py next <slug> "Check back as agreed" --due <date>`; stage stays `nurture` |
   | `referral` | Thank them; a 3-line email to the named person saying who referred you (`vintoria-outreach`) |
   | `out_of_office` | Nothing to write; the triage moves the queued emails past their return date |
   | `send_info` | ONE specific thing (a 2-minute teardown of their page, one case study from the profile) + one easy question |
   | `how_got_email` | Say honestly where the address came from and offer to remove them |
   | `wrong_person` | Ask once who owns it; no name → stop |
   | `not_interested` | One gracious line, no pitch, never follow up again |
   | `unsubscribe` / `bounce` | Nothing to write — confirm it's suppressed / find another verified contact |
   **"How much?"** — follow `../vintoria-sales/references/pricing-policy.md`: a price only if the profile has it;
   otherwise "Depends on scope — two quick questions and I'll send a written scope with options."
4. **Short and matched:** at most ~100 words before the slots and signature, not much longer than their message, their
   questions answered in the first two sentences, at most one `[TO CONFIRM]`.
5. Claim-check, show the user, and log it when sent:
   `python <SCRIPTS>/outreach/outreach.py log <slug> --channel email --to <email> --subject "Re: <their subject>" --no-schedule`. Tell the user the new stage
   and the next step with its date.

## Book

1. **Their time zone** from their post, site address, phone code (+91 India, +1 US/Canada, +44 UK, +61 Australia) or
   signature; record it once: `python <SCRIPTS>/core/pipeline.py where <slug> --country US --tz America/Chicago`.
2. **Slots:** if they named a time, use it. Otherwise `python <SCRIPTS>/replies/meeting.py slots --prospect-tz <IANA zone> [--count 3] [--minutes 30]`
   — 2 slots on different days in both zones (two concrete times beat a bare link), skipping booked meetings, plus a ready
   message with `BOOKING_URL`. India ↔ US slots marked `outside_your_work_hours` need the user's OK.
3. **When they confirm:**
   `python <SCRIPTS>/replies/meeting.py book <slug> --start "YYYY-MM-DD HH:MM" [--tz <zone of that time>] --prospect-tz <their zone> --attendee <email> --attendee-name "<name>" [--link <video link>] [--agenda "<one line>"]`
   — writes `prospects/<slug>/MEETING-<date>.ics`, sets stage `meeting`, stops follow-ups, schedules prep for the day before.
   Give the user the confirmation and tell them to attach the `.ics`.
4. **Before:** run `vintoria-close` (prep + discovery). The day before, a confirmation that carries something useful — the
   agenda and the 2-3 audit findings you'll walk through (a pre-read raises show rates); an hour before, one line.
5. **After:** `python <SCRIPTS>/replies/meeting.py outcome <id> held|no_show|rescheduled|cancelled --notes "<what was agreed>"`. Held → `vintoria-close`
   (discovery score, proposal) and the post-meeting recap in `vintoria-outreach`. No-show → the same day, one warm note with
   2 new slots; a second no-show moves them to `nurture`.

## Rules
- Reply within the hour to `meeting_request` and `interested` — speed decides most deals.
- The booking link goes out only after interest; `outreach.py` refuses it in cold emails. Bookings made through the link
  are picked up by `python <SCRIPTS>/replies/inbox.py check --apply` (and the autopilot) automatically.
- Times in **their** zone first, Vintoria's in brackets. Never invent a video link (`--link`, `MEETING_LINK`, or "link to follow").
- A proposed slot is not a meeting: book only what the prospect confirmed.

## Before anything is sent

- **Claim check** every message: `python <SCRIPTS>/outreach/claim_check.py --draft <file> --prospect <slug> [--evidence-text "<their post>"]`.
  Rewrite or delete each unsupported sentence and fill every `[PLACEHOLDER]`. Drafts never count as evidence;
  claims about the seller are checked against the real proof in the profile; a hedged consequence ("so phone
  visitors may…") is fine, an unproven number is not.
- **Compliance:** follow `references/compliance.md` — opt-out line, postal address (US), consent rules (UK/EU/CA/AU/NZ).
- **Approval:** show the user the exact final text. Nothing goes out without their OK (a sequence is approved once,
  as a whole).
- **Quality bar:** score it with `../vintoria-sales/references/quality-bar.md` (emails: 80 to show, 85+ is premium).
- **Language:** plain English by default — US spelling for US/CA, UK spelling for UK/IE/AU/NZ, clear Indian English for
  India (no "do the needful", "revert", "kindly"). If an Indian prospect wrote in Hindi or Hinglish, answer in the same
  register, still short and professional. Prices only in their currency and only from the profile.
- **Delivery:** `python <SCRIPTS>/outreach/outreach.py doctor` tells you the mode — `autopilot` (queue the approved sequence with
  `outreach.py approve`; it sends each email on its day and stops on any reply), `send-one-by-one` (`outreach.py send`,
  dry run first, then `--send`), or `manual` (the user sends; you `outreach.py log` it so follow-ups get scheduled).
  Never say something was sent unless a script returned `"sent": true` or the user told you so.
- **No booking link** (Calendly, Cal.com, `BOOKING_URL`) until they've replied with interest — a calendar link in a
  cold email reads as presumptuous and lowers replies; `outreach.py` refuses it.
- Never post, comment or DM on social platforms yourself — give the user the text (or a WhatsApp click-to-chat link).
